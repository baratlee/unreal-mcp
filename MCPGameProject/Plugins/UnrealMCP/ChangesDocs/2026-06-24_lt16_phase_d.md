## 改动详情

### 1. DataTable 读取（新命令 get_datatable_info）

**新文件**：`Private/Commands/UnrealMCPDataTableCommands.cpp`、`Public/Commands/UnrealMCPDataTableCommands.h`  
**Bridge 注册**：`UnrealMCPBridge.h`（include + 成员）、`UnrealMCPBridge.cpp`（ctor/dtor + 路由）

**命令**：`get_datatable_info(asset_path, row_name?)`
- `asset_path`：`/Game/...` 全路径，自动补全 `.AssetName` 后缀
- `row_name`（可选）：指定行名只返回该行，缺省返回全部行
- 返回：`{asset_path, row_struct, columns[], rows: {row_name: {field: value}}, row_count}`
- 使用 `UDataTable::GetTableAsJSON()` / `GetTableRowAsJSON()` 内置导出（完整类型感知）；解析失败时回退为 `rows_raw` 字符串

**调用示例**：
```json
{"asset_path": "/Game/Data/DT_CharacterStats", "row_name": "Human"}
```

### 2. PIE 控制 + 关卡切换（3 个新命令）

**文件**：`Private/Commands/UnrealMCPEditorCommands.cpp`、`Public/Commands/UnrealMCPEditorCommands.h`  
**Bridge**：EditorCommands 路由块追加

**命令**：
- `start_pie`：调 `GEditor->RequestPlaySession(FRequestPlaySessionParams())`；已在 PIE 中时返 success=false + message
- `stop_pie`：调 `GEditor->RequestEndPlayMap()`；未在 PIE 中时同上
- `open_level(map_path)`：调 `UEditorLevelLibrary::LoadLevel(map_path)`，map_path 格式 `/Game/Levels/MyMap`

**注意**：
- `start_pie` 是"请求"而非同步启动，PIE 实际开始在下一帧
- `stop_pie` 之后资产改动才可落盘（[[feedback_mcp_no_pie]] 约定）
- `open_level` 阻塞 Game Thread，避免在 PIE 中调用

---

### 3. 关卡 Actor 组件属性写入（新命令 set_actor_component_property）

**文件**：`Private/Commands/UnrealMCPEditorCommands.cpp`、`Public/Commands/UnrealMCPEditorCommands.h`  
**Bridge**：EditorCommands 路由块追加

**命令**：`set_actor_component_property(actor_label, component_name, property_name, value)`
- 在当前 Level（GWorld）按 `ActorLabel` 找 Actor
- `GetComponents()` 按 `GetName()` 找组件
- `SetObjectProperty` 写入（自动支持点分嵌套路径）
- **注意**：写入的是 World 实例（不是 CDO），不持久化到 BP 资产；级别退出后恢复
- 比 `set_component_property`（写 BP CDO）的使用场景不同：用于运行时/PIE 前的关卡调试

**调用示例**：
```json
{
  "actor_label": "BP_SpotLight_1",
  "component_name": "LightComponent",
  "property_name": "Intensity",
  "property_value": 5000.0
}
```

### 4. compile_blueprint 返回编译错误日志

**文件**：`Private/Commands/UnrealMCPBlueprintCommands.cpp`

**改前**：裸 `FKismetEditorUtilities::CompileBlueprint(Blueprint)` 调用，响应只有 `compiled: true`  
**改后**：使用 `FCompilerResultsLog`（`bSilentMode=true`）捕获编译输出，响应新增：
- `success`：`error_count == 0`
- `error_count` / `warning_count`
- `compile_log: [{severity: "error"|"warning"|"info", message: "..."}]`

**用途**：MCP 改完 BP 后立刻 `compile_blueprint` 检查编译是否成功，无需人工看 Output Log。

## 编译修复记录（2026-06-24）

初版有 4 处编译/链接问题，均已修复：

| 问题 | 根因 | 修复 |
|---|---|---|
| `KismetCompilerTypes.h` not found | 头文件路径错误 | 改 `#include "KismetCompiler.h"` |
| `GetRowStructName()` 不存在 | UE 5.7 无此 API | 改 `GetRowStruct()->GetName()` |
| `GetTableRowAsJSON()` 不存在 | UE 5.7 无此 API | 改 `GetTableAsJSON()` + 按 key 过滤 |
| `EMessageSeverity::CriticalError` 已废弃 | UE 5.7 移除此枚举值 | 删除该分支 |
| `FTokenizedMessage::GetMessageText()` 不存在 | 实际方法名为 `ToText()` | 改 `Msg->ToText().ToString()` |
| LNK2019 `ULevelEditorSubsystem` | Build.cs 缺 `LevelEditor` 模块 | 在 editor-only PrivateDependency 加 `"LevelEditor"` |

## 风险

- `set_actor_component_property` 写的是 World 实例，关卡重载后丢失（区别于 `set_component_property` 写 CDO）
- `compile_blueprint` `bSilentMode=true` 可能遗漏某些 UE 日志通道；重要错误建议同时看 Output Log 窗口

## 验证步骤

### DataTable
1. `get_datatable_info(asset_path="/Game/.../DT_XXX")` 验证返回 `columns + rows`
2. `get_datatable_info(asset_path=..., row_name="SomeRow")` 验证只返回指定行

### PIE
1. `start_pie` → 验证编辑器进入 PIE
2. `stop_pie` → 验证退出 PIE
3. 未在 PIE 时调 `stop_pie` 验证返回 `success=false + message`

### open_level
1. `open_level(map_path="/Game/Levels/SomeMap")` 验证编辑器切换地图

### set_actor_component_property
1. 关卡中有已加载 Actor，调用写组件属性（如灯光 Intensity）
2. Details 面板查看值已更新

### compile_blueprint
1. `compile_blueprint(blueprint_name="BP_KLPawn_Human")` 验证返回 `success=true, error_count=0, compile_log`
2. 手动在 BP 里引入编译错误，再调 compile 验证 `success=false, compile_log` 有 error 条目
