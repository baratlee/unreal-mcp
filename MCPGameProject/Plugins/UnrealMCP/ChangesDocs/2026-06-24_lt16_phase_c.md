# LT16 Phase C — AnimNotify index 统一 + FStructProperty 嵌套写 + ArrayProperty Phase B + 子蓝图落盘

日期：2026-06-24  
关联：PrjKunlun LT16 UnrealMCP 持续扩展

---

## 背景

四个相互独立的能力缺口，合并为一个批次落地：

1. `get_animation_notifies` 输出的下标与 `set/remove/details` 使用的下标不一致
2. `SetObjectProperty` 嵌套路径碰到 FStructProperty 头节点直接报错
3. `TArray<FStruct>` 无法写入（Phase A 只支持 scalar/FName/FString/SoftObject）
4. `set_blueprint_property` 对子蓝图（继承自父 BP）写的值在 compile+save 后丢失

---

## 改动详情

### 1. AnimNotify index 统一

**文件**：`Private/Commands/UnrealMCPAnimationCommands.cpp`  
**函数**：`HandleGetAnimationNotifies`

**改前**：用 `UAnimationBlueprintLibrary::GetAnimationNotifyEvents()` 的排序副本遍历，返回的下标 i 是排序后的位置，与 `AnimBase->Notifies[i]`（`set/remove/details` 使用的 raw index）不一致。

**改后**：直接遍历 `AnimBase->Notifies`（raw 数组），每个条目新增 `raw_index` 字段。调用方用 `raw_index` 调 `set_animation_notify` / `remove_animation_notify` / `get_animation_notify_details`。

**注意**：输出顺序从"时间序"变为"存储序"；`raw_index` 新增字段，不破坏既有字段。

---

### 2. FStructProperty 嵌套写入

**文件**：`Private/Commands/UnrealMCPCommonUtils.cpp`  
**函数**：`SetObjectProperty`（嵌套路径分支）

**改前**：点分路径头节点只处理 `FObjectProperty`（instanced UObject），碰到 `FStructProperty`（如 `BodyInstance`）直接返错。

**改后**：新增 `FStructProperty` 分支，沿路径段逐层定位（支持任意深度，中间段须全为 FStructProperty），叶子字段用 `ImportText_Direct` 写入。

**附加修复（验证期间发现）**：`set_component_property` 的 `HandleSetComponentProperty` 用 `FindFProperty` 做精确名匹配，无法处理点分路径，导致 `SetObjectProperty` 的 FStructProperty 分支根本触达不到。已在 `HandleSetComponentProperty` 中添加早返分支：点分路径直接路由 `SetObjectProperty`，普通路径走原有逻辑不变。

**支持的叶子值类型**：JSON string / number / bool → 自动转字符串后喂 ImportText。

**调用示例**：
```json
{
  "property_name": "BodyInstance.CollisionProfileName",
  "property_value": "OverlapAllDynamic"
}
```

---

### 3. ArrayProperty Phase B — TArray\<FStruct\>

**文件**：`Private/Commands/UnrealMCPCommonUtils.cpp`  
**变更**：顶部新增 `#include "JsonObjectConverter.h"`；改写 Phase A 代码块。

**改前**：Phase A 遇到 JSON Object 元素直接报错退出。

**改后**：在 Phase A 之前先检测 `ArrProp->Inner` 是否为 `FStructProperty`：
- **Phase B（是）**：`FScriptArrayHelper::Resize()` + 每个元素 `InitializeStruct` + `FJsonObjectConverter::JsonObjectToUStruct()`
- **Phase A（否）**：T3D ImportText 路径不变

**调用示例（写 GE Modifiers）**：
```json
{
  "property_name": "Modifiers",
  "property_value": [
    {"Attribute": "...", "ModifierOp": 0, "Magnitude": {...}}
  ]
}
```

**注意**：`JsonObjectToUStruct` 字段名区分大小写，须与 UStruct 字段名（C++ 反射名）完全一致。

---

### 4. 子蓝图属性落盘

**文件**：`Private/Commands/UnrealMCPBlueprintCommands.cpp`  
**函数**：`HandleSetBlueprintProperty`

**改前**：只写 CDO，`MarkBlueprintAsModified` 后 compile+save 可能丢失改动（编译时 CDO 从 blueprint 元数据重建，覆盖 in-memory 写入）。

**改后**：
1. 写之前 `Blueprint->Modify()` + `DefaultObject->Modify()`，让两个对象都进入 UE 事务
2. 写之后，若属性在 `Blueprint->NewVariables` 中，用 `ExportTextItem_Direct` 导出值写回 `VarDesc.DefaultValue`，确保编译时 CDO 重建用正确值

**局限**：属性继承自父 Blueprint（非 C++ 基类）且不在当前 BP `NewVariables` 时，返回 `"warning"` 字段提示需在 compile 后用 `get_blueprint_cdo_properties` 验证。

## 覆盖矩阵

| 命令 | 新场景 | 已有场景 |
|---|---|---|
| `get_animation_notifies` | 新增 `raw_index` 字段 | 其他字段不变 |
| `set_blueprint_property` | FStructProperty 嵌套路径 | FObjectProperty 嵌套路径不变 |
| `set_blueprint_property` | TArray\<FStruct\> 写入 | TArray\<scalar\> 路径不变 |
| `set_blueprint_property` | 子蓝图落盘增强 | 非子蓝图行为不变 |

---

## 风险

- FStructProperty 嵌套：`ImportText_Direct` 对复杂嵌套类型（如 FGameplayTagContainer）行为依赖 UE 序列化实现，需实证验证
- ArrayProperty Phase B：`FJsonObjectConverter` 字段名大小写敏感，传错名字会静默跳过而非报错
- 子蓝图落盘：继承自父 BP 的属性仍可能在 compile 后重置，通过 warning 字段提示调用方验证

---

## 验证步骤

### AnimNotify index
1. 对任意有多个 notify 的 AnimSequence/Montage 调 `get_animation_notifies`
2. 确认每个条目有 `raw_index` 字段，值为 0, 1, 2... 连续整数
3. 用 `raw_index` 调 `set_animation_notify(notify_index=raw_index, trigger_time=X)`，再 get 验证时间已更新

### FStructProperty 嵌套
1. 对含 `BodyInstance` 的 Static/Skeletal Mesh Component 所在 BP，调 `set_blueprint_property(property_name="BodyInstance.CollisionProfileName", property_value="OverlapAllDynamic")`
2. 调 `get_component_properties` 验证 CollisionProfileName 已更新

### ArrayProperty Phase B
1. 构造一个 `TArray<FGameplayModifierInfo>` 类型属性的 GE，调 `set_blueprint_property(property_name="Modifiers", property_value=[{...}])`
2. 用 `get_gameplay_effect_info` 验证 Modifiers 数组已更新

### 子蓝图落盘
1. 找一个继承自父 BP 的子 BP，调 `set_blueprint_property` 设某个在 `NewVariables` 中声明的属性
2. 在编辑器手动 Compile + Save
3. 重开编辑器，用 `get_blueprint_cdo_properties` 验证值未丢失
